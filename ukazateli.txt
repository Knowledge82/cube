Как работает передача адреса поля структуры?
Ебать, Повелитель сучек, да тут важная тема про указатели и структуры, блять! Давай разберём детально, что происходит под капотом! 🔥

Что такое &game.config?
Когда ты пишешь:

t_game game;
parse_config(file, map_start, &game.config);
Что происходит:

game — это структура на стеке (по адресу, допустим, 0x1000)
game.config — это поле структуры game (находится внутри game по смещению от начала структуры)
&game.config — это адрес поля config внутри структуры game

Расчёт адреса поля:
Допустим, структура t_game выглядит так:

typedef struct s_game
{
    mlx_t    *mlx;      // Смещение: 0 байт (8 байт)
    t_map    map;       // Смещение: 8 байт (32 байта)
    t_config config;    // Смещение: 40 байт (48 байт)
    t_player player;    // Смещение: 88 байт (48 байт)
}   t_game;
Если game находится по адресу 0x1000:

&game = 0x1000 (адрес начала структуры)
&game.mlx = 0x1000 + 0 = 0x1000
&game.map = 0x1000 + 8 = 0x1008
&game.config = 0x1000 + 40 = 0x1028 ← ВОТ ЭТО!
&game.player = 0x1000 + 88 = 0x1058
Так что &game.config — это просто адрес в памяти, где начинается поле config внутри структуры game, дружок-пирожок! 💪

Что получает функция parse_config?
int parse_config(char **file, int map_start, t_config *config)
{
    config->north = ...;  // config — это УКАЗАТЕЛЬ (адрес 0x1028)
}
Функция получает:

config = 0x1028 (адрес поля config внутри game)
Когда функция пишет config->north = ...:

Она обращается к памяти по адресу 0x1028 (начало config)
Изменяет поле north внутри config
Это изменяет поле config внутри структуры game, блять! 💪

Визуализация в памяти:
Память (до вызова parse_config):

Адрес:     Содержимое:
0x1000     [mlx = NULL]
0x1008     [map.grid = NULL]
           [map.width = 0]
           ...
0x1028     [config.north = NULL]   ← ВОТ config!
           [config.south = NULL]
           [config.west = NULL]
           ...
0x1058     [player.pos_x = 0.0]
           ...

Вызов:
parse_config(file, map_start, &game.config);  // Передаём адрес 0x1028

Внутри parse_config:
config->north = ft_strdup("path/to/north.png");  // Пишем по адресу 0x1028

Память (после parse_config):

Адрес:     Содержимое:
0x1000     [mlx = NULL]
0x1008     [map.grid = NULL]
           ...
0x1028     [config.north = 0x2000]  ← ИЗМЕНИЛОСЬ!
           [config.south = NULL]
           ...
Видишь? Функция изменила память внутри структуры game, передавая адрес поля config, дружок-пирожок! 🔥

Почему это работает?
Потому что указатель — это просто адрес в памяти, блять! Неважно, откуда этот адрес — из malloc или из поля структуры на стеке! Функция не знает и не должна знать, где именно находится эта память — на стеке или на куче, Валерка! 💪

Главное — адрес валидный и память доступна для записи, красавчик! ✅
