## Что такое Ray Casting?

**Ray Casting** — техника рендеринга псевдо-3D графики (2.5D), которая создаёт иллюзию трёхмерного пространства на основе двумерной карты.

### Основная идея:
**Для каждого вертикального столбца экрана:**
1. Выпускаем луч из позиции игрока
2. Луч летит по карте, пока не врежется в стену
3. Измеряем расстояние до стены
4. Рисуем вертикальную полоску: чем ближе стена — тем выше полоска

**Результат для разрешения 640x480:** 640 вертикальных полосок разной высоты, которые создают иллюзию 3D-лабиринта.

Эта техника позволяла запускать игры на процессорах начала 90-х годов — никакой настоящей 3D-графики, только умная математика!

## Парсинг конфигурации

Находим начало карты *map_start*. Всё что выше - конфиг, всё что ниже - карта. Парсим конфиг:  
- разбираем строки с идентификаторами `NO`, `SO`, `WE`, `EA`, `F`, `C`  
- извлекаем пути к текстурам и значения RGB  
- например, строка: `NO ./textures/north_wall.png` разбирается на:  
	- идентификатор: `NO`  
	- путь: `./textures/north_wall.png`  

Проверки:  
✅ Идентификатор корректный (NO/SO/WE/EA)  
✅ Путь указан и не пустой  
✅ Файл текстуры существует  
✅ Каждая текстура указана ровно один раз  

Парсинг цветов:
Строка: `F 220,100,0`:  
идентификатор: `F` (floor)  
RGB: R=220, G=100, B=0  

Проверки:  
✅ Формат: R,G,B (без пробелов вокруг запятых)  
✅ Каждое значение — число от 0 до 255  
✅ Ровно 3 компонента (R, G, B)  
✅ F и C указаны ровно один раз  

**Конвертация RGB в hex:**  
R=220, G=100, B=0  
hex = (R << 16) | (G << 8) | B  
hex = 0xDC6400  
MLX42 принимает цвет в формате RGBA (A - прозрачность), а не RGB как MiniLibX, поэтому перед использованием сдвинем цвет ещё на 8 бит (<< 8).

## Валидация карты

### Проверка замкнутости карты

**Что такое "замкнутая" карта?**  
Замкнутая карта — это карта, где все доступные для игрока клетки (символы `0`, `N/S/E/W`) окружены стенами (`1`). Игрок не должен иметь возможности "выйти" за пределы игровой зоны. Если в карте есть дыра (пробел на границе доступной области), это приведёт к неопределённому поведению при рендеринге.

**Ключевой критерий незамкнутости:**  
***❌ Карта незамкнута, если любая доступная клетка (`0`) граничит с пробелом (` `).***

Другими словами:  
✅ Клетка `0` может соседствовать с `0` (другая доступная клетка)  
✅ Клетка `0` может соседствовать с `1` (стена — граница игровой зоны)  
❌ Клетка `0` НЕ МОЖЕТ соседствовать с ` ` (пробел — пустота за картой)  

**О пробелах в карте:**  
Пробел — это легальный символ в файле `.cub`. Он используется для:
- Выравнивания карты (отступы слева)
- Обозначения "ничего" за пределами игровой зоны

Пример валидного использования пробелов:
```
  111111111111    ← Пробелы слева для отступа (OK)
  100000000001
111N0111100111
100001 10001      ← Пробел внутри окружён стенами (OK)
111111 11111
```

Но если пробел граничит с доступной клеткой — это дыра:
```
11111111
1000000           ← Пробел справа граничит с `0` — ДЫРА!
100N0001
10000001
11111111
```

### BFS для проверки замкнутости

Для проверки замкнутости карты используется итеративный алгоритм поиска в ширину — **Breadth-First Search (BFS)**.

<p align="left">
  <img src="./images/DFSvsBFS.gif" alt="DFS vs BFS" width="300">
</p>

**Почему BFS, а не рекурсивный Flood Fill (DFS)?**

| Критерий | BFS (итеративный) | DFS (рекурсивный) |
|----------|-------------------|-------------------|
| Безопасность | ✅ Нет риска переполнения стека | ❌ Может упасть на больших картах |
| Сложность | O(width × height) | O(width × height) |
| Память | Очередь размером width × height | Стек вызовов (непредсказуемо) |
| Читаемость | ✅ Итеративный код легко отлаживать | Сложнее отследить рекурсию |
| Полнота | ✅ Гарантированно обходит все клетки | ✅ Обходит все клетки |

---

### Структуры данных для BFS

**Точка на карте:**
```c
typedef struct s_point
{
    int x;  // Координата X
    int y;  // Координата Y
} t_point;
```

**Круговая очередь:**
```c
typedef struct s_queue
{
    t_point *data;         // Массив точек
    int     first;         // Индекс первого элемента
    int     last;          // Индекс последнего элемента
    int     current_size;  // Текущее количество элементов
    int     capacity;      // Максимальная вместимость
} t_queue;
```

**Почему круговая очередь?**
- **Эффективное использование памяти:** после `dequeue` место освобождается и переиспользуется
- **O(1) для операций:** `enqueue` и `dequeue` выполняются за константное время
- **Избегаем сдвигов:** не нужно постоянно сдвигать элементы массива

**Данные для BFS:**
```c
typedef struct s_bfs_data
{
    int     **visited;  // Матрица посещённых клеток (0 или 1)
    t_queue *queue;     // Очередь для обхода
} t_bfs_data;
```

---

### Как работает алгоритм

**Инициализация (`init_bfs`):**
1. Создаём матрицу `visited` размером `[height][width]` (все значения = `0`)
2. Создаём круговую очередь размером `height × width`
3. Находим стартовую позицию игрока (`N`, `S`, `E`, `W`)
4. Добавляем стартовую позицию в очередь
5. Помечаем стартовую клетку как посещённую (`visited[y][x] = 1`)

**Обход в ширину (`process_bfs`):**

Пока очередь не пуста:
1. Извлекаем клетку из очереди (`dequeue`)
2. Проверяем **4 соседних клетки** (вверх, вниз, влево, вправо)
3. Для каждого соседа вызываем `check_cell`:
   - Если это `0` (доступная клетка):
     - Помечаем как посещённую
     - Добавляем в очередь
   - Если это `1` (стена):
     - Игнорируем (это граница игровой зоны)
   - Если это ` ` (пробел):
     - **ОШИБКА!** Доступная клетка граничит с пустотой
     - Карта не замкнута → возвращаем `0`

**Результат:**
- ✅ Все доступные клетки проверены без встречи с пробелами → карта замкнута
- ❌ Хотя бы одна доступная клетка граничит с пробелом → карта незамкнута

---

### Ключевые функции

| Функция | Назначение |
|---------|------------|
| `init_bfs` | Инициализация BFS: создаёт матрицу `visited`, очередь, добавляет стартовую позицию |
| `process_bfs` | Основной цикл обхода: извлекает клетку, проверяет соседей, возвращает результат |
| `check_cell` | Проверяет конкретную клетку: `0` → добавить в очередь, `1` → игнорировать, ` ` → ошибка |
| `can_visit` | Проверяет, можно ли посетить клетку: в границах карты и не посещалась ранее |
| `enqueue` | Добавляет клетку в очередь (с учётом круговой структуры) |
| `dequeue` | Извлекает клетку из очереди |

## Инициализация игрока и камеры

После успешного парсинга карты необходимо инициализировать позицию игрока и настроить "камеру". Это происходит в функции `init_player()`.

### Позиция игрока

Игрок находится в клетке, где был обнаружен символ `N`, `S`, `E` или `W`:
- `player.pos_x` — координата X в сетке карты (например, 5.5 — центр клетки)
- `player.pos_y` — координата Y в сетке карты

Позиция игрока хранится в структуре `t_player`:
```c
typedef struct s_player
{
    double  pos_x;      // Позиция X
    double  pos_y;      // Позиция Y
    double  dir_x;      // Направление взгляда X
    double  dir_y;      // Направление взгляда Y
    double  plane_x;    // Плоскость камеры X
    double  plane_y;    // Плоскость камеры Y
} t_player;
```

### Вектор направления взгляда (direction vector)

---
<p align="left">
  <img src="./images/raycasting2.png" alt="Raycasting" width="300">
</p>
---
Определяет, куда смотрит игрок. Это единичный вектор:
- `dir_x` и `dir_y` образуют вектор направления
- Зависит от начального символа на карте (`map.start_dir`):
  - `N` (North): `dir_x = 0`, `dir_y = -1` (смотрит вверх)
  - `S` (South): `dir_x = 0`, `dir_y = 1` (смотрит вниз)
  - `E` (East): `dir_x = 1`, `dir_y = 0` (смотрит вправо)
  - `W` (West): `dir_x = -1`, `dir_y = 0` (смотрит влево)

### Плоскость камеры (camera plane)

Плоскость камеры — это перпендикулярный вектор к направлению взгляда. Она определяет поле зрения (Field of View, FOV):
- `plane_x` и `plane_y` — координаты вектора плоскости камеры
- Длина этого вектора определяет угол обзора
- Типичное значение длины: `0.66` (примерно 66° FOV)

**Пример для игрока, смотрящего на север (N):**
```c
player.dir_x = 0.0;
player.dir_y = -1.0;
player.plane_x = 0.66;   // Перпендикуляр к направлению
player.plane_y = 0.0;
```

**Почему плоскость перпендикулярна?**  
Плоскость камеры — это "экран" в игровом мире. Лучи проходят через эту плоскость, создавая конус обзора. Чем длиннее вектор плоскости, тем шире FOV.

## Цикл по столбцам экрана

Рейкастинг выполняется **для каждого вертикального столбца экрана**. Если разрешение экрана `800×600` (WIDTH × HEIGHT), то нужно выпустить 800 лучей.

Основной цикл в функции `render_frame()`:
```c
void render_frame(t_game *game)
{
    t_ray ray;
    int x;

    x = 0;
    while (x < WIDTH)
    {
        init_ray(game, x, &ray);     // Инициализация луча
        dda(game, &ray);              // DDA алгоритм
        calculate_wall_distance(game, &ray);  // Расчёт расстояния
        draw_column(game, x, &ray);   // Рендеринг столбца
        x++;
    }
}
```

### Расчёт направления луча

Для каждого столбца `x` (от 0 до WIDTH - 1) в функции `init_ray()`:

**1. Нормализованная координата камеры:**
```c
double camera_x = 2 * x / (double)WIDTH - 1;
```
- Значение от `-1` (левый край экрана) до `+1` (правый край)
- При `x = 0`: `camera_x = -1`
- При `x = WIDTH/2`: `camera_x = 0` (центр)
- При `x = WIDTH-1`: `camera_x ≈ +1`

**2. Направление луча:**
```c
ray->dir_x = game->player.dir_x + game->player.plane_x * camera_x;
ray->dir_y = game->player.dir_y + game->player.plane_y * camera_x;
```
- Луч проходит через плоскость камеры
- Центральный луч (`camera_x = 0`) совпадает с направлением взгляда
- Боковые лучи отклоняются влево/вправо

**Почему это работает?**
- Центральный луч: `ray_dir = dir + plane * 0 = dir` (чистое направление взгляда)
- Левый край: `ray_dir = dir + plane * (-1)` (отклонение влево)
- Правый край: `ray_dir = dir + plane * (+1)` (отклонение вправо)

**3. Текущая клетка карты:**
```c
ray->map_x = (int)game->player.pos_x;
ray->map_y = (int)game->player.pos_y;
```

## DDA алгоритм
---
<p align="left">
  <img src="./images/dda.png" alt="DDA raycasting" width="300">
</p>
---

**DDA (Digital Differential Analyzer)** — алгоритм, который позволяет лучу "шагать" по сетке карты до столкновения со стеной.

### Основная идея

Луч движется по карте, пересекая границы клеток. DDA определяет:
- В какой клетке находится луч
- Какую границу клетки он пересекает следующей (вертикальную или горизонтальную)
- Расстояние до этой границы

### Инициализация DDA

Функция `init_ray()` вызывает вспомогательные функции из `ray_utils.c`:

**1. Расчёт delta_dist (`calculate_delta_dist()`):**
```c
ray->delta_dist_x = fabs(1.0 / ray->dir_x);
ray->delta_dist_y = fabs(1.0 / ray->dir_y);
```
- `delta_dist_x` — расстояние, которое луч проходит при сдвиге на 1 клетку по X
- `delta_dist_y` — аналогично для Y

**2. Направление шага и начальное расстояние (`init_step_and_side_dist()`):**

Если луч идёт в положительном направлении X (`ray->dir_x > 0`):
```c
ray->step_x = 1;
ray->side_dist_x = (ray->map_x + 1.0 - game->player.pos_x) * ray->delta_dist_x;
```

Если луч идёт в отрицательном направлении X (`ray->dir_x < 0`):
```c
ray->step_x = -1;
ray->side_dist_x = (game->player.pos_x - ray->map_x) * ray->delta_dist_x;
```

Аналогично для Y.

- `step_x/step_y` — направление движения по сетке (+1 или -1)
- `side_dist_x/side_dist_y` — расстояние до следующей границы клетки

### Цикл DDA

Функция `dda()` выполняет обход сетки:

Луч "шагает" по карте, пока не врежется в стену (`map->grid[ray->map_y][ray->map_x] == '1'`):

```c
void dda(t_game *game, t_ray *ray)
{
    int hit;

    hit = 0;
    while (hit == 0)
    {
        // Выбираем, какую границу пересечь следующей
        if (ray->side_dist_x < ray->side_dist_y)
        {
            ray->side_dist_x += ray->delta_dist_x;  // Сдвигаемся по X
            ray->map_x += ray->step_x;
            ray->side = 0;  // Вертикальная граница (West/East)
        }
        else
        {
            ray->side_dist_y += ray->delta_dist_y;  // Сдвигаемся по Y
            ray->map_y += ray->step_y;
            ray->side = 1;  // Горизонтальная граница (North/South)
        }
        
        // Проверяем столкновение со стеной
        if (game->map.grid[ray->map_y][ray->map_x] == '1')
            hit = 1;
    }
}
```

**Переменная `ray->side`:**
- `side = 0` — луч попал в вертикальную стену (West или East)
- `side = 1` — луч попал в горизонтальную стену (North или South)

Это важно для:
- Выбора правильной текстуры (NO/SO/WE/EA)
- Затенения (вертикальные стены часто делают темнее для эффекта глубины)

---

## Расчёт расстояния до стены

После того как луч врезался в стену, нужно вычислить **расстояние от игрока до стены**.

### Проблема: Fish-Eye эффект

Если использовать **евклидово расстояние** (по прямой от игрока до точки столкновения), получится искажение "рыбий глаз":
- Боковые стены будут казаться дальше
- Изображение будет изогнутым
- Параллельные линии будут выглядеть искривлёнными

### Решение: Перпендикулярное расстояние

Функция `calculate_wall_distance()` вычисляет **перпендикулярное расстояние** — расстояние до стены вдоль плоскости камеры.

**Формула:**

Если луч пересёк вертикальную границу (`ray->side == 0`):
```c
ray->perp_wall_dist = (ray->map_x - game->player.pos_x 
                       + (1 - ray->step_x) / 2) / ray->dir_x;
```

Если луч пересёк горизонтальную границу (`ray->side == 1`):
```c
ray->perp_wall_dist = (ray->map_y - game->player.pos_y 
                       + (1 - ray->step_y) / 2) / ray->dir_y;
```

**Почему это работает?**
- `(1 - step_x) / 2` — корректировка для направления луча (0 или 1)
- Делим на `ray->dir_x` (или `ray->dir_y`), чтобы получить проекцию на направление взгляда

**Результат:** все стены отображаются без искажений, параллельные линии остаются параллельными.

## Определение стороны столкновения

Нужно определить, с какой стороны луч врезался в стену, чтобы выбрать правильную текстуру из `t_textures`.

Функция `select_texture()` в `draw_utils.c` определяет текстуру:

```c
mlx_texture_t *select_texture(t_game *game, t_ray *ray)
{
    if (ray->side == 0)  // Вертикальная граница
    {
        if (ray->dir_x > 0)
            return (game->textures.west);   // Луч идёт вправо → западная стена
        else
            return (game->textures.east);   // Луч идёт влево → восточная стена
    }
    else  // Горизонтальная граница (ray->side == 1)
    {
        if (ray->dir_y > 0)
            return (game->textures.north);  // Луч идёт вниз → северная стена
        else
            return (game->textures.south);  // Луч идёт вверх → южная стена
    }
}
```

**Соответствие текстурам:**
- **North (NO)** — `game->textures.north` — северная стена
- **South (SO)** — `game->textures.south` — южная стена  
- **West (WE)** — `game->textures.west` — западная стена
- **East (EA)** — `game->textures.east` — восточная стена

## Расчёт высоты стены на экране

Высота стены на экране **обратно пропорциональна расстоянию** до неё: чем ближе стена, тем она выше.

**Формула:**
```c
int line_height = (int)(HEIGHT / ray->perp_wall_dist);
```

Где:
- `HEIGHT` — высота экрана (600 пикселей)
- `ray->perp_wall_dist` — перпендикулярное расстояние до стены

**Пример:**
- Если расстояние = 1.0 → высота стены = 600 пикселей (занимает весь экран)
- Если расстояние = 2.0 → высота стены = 300 пикселей (половина экрана)
- Если расстояние = 10.0 → высота стены = 60 пикселей (очень далеко)

---

## Определение границ отрисовки

Стена должна быть **вертикально центрирована** на экране. Нужно вычислить, с какого пикселя начать рисовать и где закончить.

**Расчёт начальной и конечной точки:**
```c
int draw_start = -line_height / 2 + HEIGHT / 2;
int draw_end = line_height / 2 + HEIGHT / 2;
```

**Проблема:** стена может быть **очень близко** и её высота превысит высоту экрана.

**Решение — клиппинг (обрезка):**
```c
if (draw_start < 0)
    draw_start = 0;
if (draw_end >= HEIGHT)
    draw_end = HEIGHT - 1;
```

Эти значения хранятся в структуре `t_wall_draw`:
```c
typedef struct s_wall_draw
{
    mlx_texture_t   *current_texture;  // Выбранная текстура
    int             line_height;       // Высота стены
    int             draw_start;        // Начало отрисовки (Y)
    int             draw_end;          // Конец отрисовки (Y)
    int             tex_x;             // X-координата на текстуре
    int             clipped_top;       // Сколько пикселей обрезано сверху
} t_wall_draw;
```

**Зачем `clipped_top`?**  
Если стена очень близко и `draw_start` был < 0, нам нужно знать, сколько пикселей текстуры было обрезано сверху. Это важно для правильного маппинга текстуры.

```c
int clipped_top = 0;
if (draw_start < 0)
    clipped_top = -draw_start;
```

## Отрисовка пола и потолка

Перед отрисовкой стены заполняем верхнюю и нижнюю части столбца **сплошным цветом**.

**Функция `draw_column()` в `draw.c`:**

**1. Потолок (от 0 до `draw_start`):**
```c
int y = 0;
while (y < draw_start)
{
    mlx_put_pixel(game->image, x, y, game->config.ceiling_color);
    y++;
}
```

**2. Пол (от `draw_end` до `HEIGHT`):**
```c
y = draw_end;

{
    mlx_put_pixel(game->image, x, y, game->config.floor_color);
    y++;
}
```

Цвета `ceiling_color` и `floor_color` задаются в конфигурационном файле `.cub` (строки `C` и `F`) и хранятся в `t_config` в формате `uint32_t` (RGBA).

## Работа с текстурами

### Выбор текстуры

Функция `select_texture()` в `draw_utils.c` определяет, какую текстуру использовать на основе стороны столкновения:

```c
mlx_texture_t *select_texture(t_game *game, t_ray *ray)
{
    if (ray->side == 0)  // Вертикальная граница
    {
        if (ray->dir_x > 0)
            return (game->textures.west);
        else
            return (game->textures.east);
    }
    else  // Горизонтальная граница
    {
        if (ray->dir_y > 0)
            return (game->textures.north);
        else
            return (game->textures.south);
    }
}
```

### Расчёт X-координаты на текстуре

Нужно определить, **какой вертикальный столбец текстуры** использовать для текущего столбца экрана.

**Функция `calculate_tex_x()` в `draw_utils.c`:**

**1. Определяем точку столкновения с стеной:**
```c
double wall_x;

if (ray->side == 0)  // Вертикальная стена
    wall_x = game->player.pos_y + ray->perp_wall_dist * ray->dir_y;
else  // Горизонтальная стена
    wall_x = game->player.pos_x + ray->perp_wall_dist * ray->dir_x;
```

`wall_x` — это координата точки столкновения на стене (дробная часть от 0.0 до 1.0).

**2. Оставляем только дробную часть:**
```c
wall_x -= floor(wall_x);
```

Теперь `wall_x` находится в диапазоне [0.0, 1.0).

**3. Конвертируем в координату текстуры:**
```c
int tex_x = (int)(wall_x * (double)texture->width);
```

**4. Инверсия для некоторых сторон:**
```c
if ((ray->side == 0 && ray->dir_x > 0) || 
    (ray->side == 1 && ray->dir_y < 0))
    tex_x = texture->width - tex_x - 1;
```

Это нужно, чтобы текстуры не были зеркально отражены на противоположных стенах.

### Масштабирование текстуры по вертикали

Текстура имеет фиксированную высоту (например, 64 или 128 пикселей), но на экране стена может быть любой высоты. Нужно **растянуть или сжать текстуру**.

**Алгоритм в `draw_column()`:**

**1. Вычисляем шаг текстуры:**
```c
double step = (double)texture->height / (double)wall_draw.line_height;
```

**2. Вычисляем начальную позицию на текстуре:**
```c
double tex_pos = wall_draw.clipped_top * step;
```

Если стена была обрезана сверху (`clipped_top > 0`), начинаем не с начала текстуры, а с соответствующей позиции.

**3. Для каждого пикселя стены:**
```c
int y = wall_draw.draw_start;
while (y < wall_draw.draw_end)
{
    // Текущая Y-координата на текстуре
    int tex_y = (int)tex_pos;
    
    // Получаем цвет пикселя из текстуры
    uint32_t color = get_texture_color(texture, wall_draw.tex_x, tex_y);
    
    // Рисуем пиксель на экране
    mlx_put_pixel(game->image, x, y, color);
    
    // Двигаемся по текстуре
    tex_pos += step;
    y++;
}
```

**Почему используется `tex_pos` (double)?**  
Текстура может быть сжата или растянута. `tex_pos` позволяет плавно "скользить" по текстуре, выбирая нужные пиксели.

## Копирование пикселей на экран

**Функция `get_texture_color()` в `draw_utils.c`:**

Извлекает цвет пикселя из текстуры MLX42:

```c
uint32_t get_texture_color(mlx_texture_t *texture, int tex_x, int tex_y)
{
    int index;
    uint32_t color;

    // Проверка границ
    if (tex_x < 0 || tex_x >= (int)texture->width || 
        tex_y < 0 || tex_y >= (int)texture->height)
        return (0xFF000000);  // Чёрный цвет при ошибке

    // Индекс в массиве пикселей
    index = (tex_y * texture->width + tex_x) * texture->bytes_per_pixel;

    // Извлекаем RGBA компоненты
    color = (texture->pixels[index] << 24) |      // R
            (texture->pixels[index + 1] << 16) |  // G
            (texture->pixels[index + 2] << 8) |   // B
            texture->pixels[index + 3];           // A

    return (color);
}
```

**Формат MLX42:**
- Текстуры хранятся в формате RGBA (4 байта на пиксель)
- `texture->pixels` — массив байтов
- `texture->bytes_per_pixel` — обычно 4

**Почему сдвиги битов?**  
MLX42 ожидает цвет в формате `0xRRGGBBAA`, поэтому нужно собрать 4 байта в одно 32-битное число.

## Загрузка текстур

Текстуры загружаются при инициализации игры функцией `load_all_textures()` в `textures.c`.

**Функция `load_texture()`:**
```c
int load_texture(mlx_texture_t **texture_field, const char *path)
{
    *texture_field = mlx_load_png(path);
    if (!(*texture_field))
    {
        error_msg("Failed to load texture");
        return (0);
    }
    return (1);
}
```

**Функция `load_all_textures()`:**
```c
int load_all_textures(t_textures *textures, t_config *config)
{
    if (!load_texture(&textures->north, config->north))
        return (0);
    if (!load_texture(&textures->south, config->south))
        return (0);
    if (!load_texture(&textures->west, config->west))
        return (0);
    if (!load_texture(&textures->east, config->east))
        return (0);
    return (1);
}
```

**Важно:**
- MLX42 поддерживает только PNG формат
- Текстуры должны существовать и быть доступны для чтения
- Рекомендуется использовать текстуры размером степени двойки (64×64, 128×128, 256×256)

| Файл | Назначение |
|------|------------|
| `draw.c` | Основная функция `draw_column()` — рисует вертикальный столбец (потолок, стену, пол) |
| `draw_utils.c` | Утилиты рендеринга: `select_texture()`, `get_texture_color()`, `calculate_tex_x()` |

## Решение проблем

### Ошибка: "Error: Invalid file extension"
**Причина:** Файл не имеет расширения `.cub`  
**Решение:** Используйте файл с правильным расширением: `map.cub`

### Ошибка: "Error: Failed to open file"
**Причина:** Файл не существует или нет прав на чтение  
**Решение:** 
- Проверьте путь к файлу
- Проверьте права доступа: `chmod 644 map.cub`

### Ошибка: "Error: Invalid map"
**Причина:** Карта не валидна (не замкнута, неправильные символы и т.д.)  
**Решение:**
- Проверьте, что карта окружена стенами (`1`)
- Проверьте, что есть ровно один игрок (`N`, `S`, `E`, `W`)
- Проверьте, что нет недопустимых символов

### Ошибка: "Error: Failed to load texture"
**Причина:** Текстура не найдена или повреждена  
**Решение:**
- Проверьте пути к текстурам в `.cub` файле
- Убедитесь, что текстуры в формате PNG
- Проверьте права доступа к файлам текстур

### Ошибка: "Error: Invalid color format"
**Причина:** Неправильный формат цвета в `.cub` файле  
**Решение:**
- Формат: `F 220,100,0` (R,G,B без пробелов)
- Значения от 0 до 255
- Ровно 3 компонента

### Ошибка: MLX не инициализируется
**Причина:** Проблемы с графической системой или GLFW  
**Решение:**
```bash
# Ubuntu/Debian
sudo apt-get install libglfw3-dev libglfw3

# Проверьте, что X11 запущен (для Linux)
echo $DISPLAY

# Если пусто, попробуйте:
export DISPLAY=:0
```

### Низкая производительность (FPS)
**Причина:** Тяжёлые текстуры или большое разрешение  
**Решение:**
- Уменьшите разрешение в `cube.h`: `#define WIDTH 640` и `#define HEIGHT 480`
- Используйте текстуры меньшего размера (64×64 вместо 256×256)
- Проверьте оптимизацию компиляции: флаг `-O2` в Makefile

### Игра не реагирует на ввод
**Причина:** Окно не в фокусе или проблема с обработкой событий  
**Решение:**
- Кликните на окно игры
- Убедитесь, что `key_handler` зарегистрирован в MLX
- Проверьте, что используется `mlx_key_hook()`

### Сегментация (Segmentation Fault)
**Причина:** Обращение к неинициализированной памяти или выход за границы массива  
**Решение:**
- Запустите с valgrind: `valgrind ./cub3D maps/map.cub`
- Проверьте инициализацию всех структур
- Проверьте границы массивов в парсинге карты
