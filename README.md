# 🧩 cub3D — Raycasting Maze Game (School 42 Project)

> 🕹️ Проект вдохновлён **Wolfenstein 3D (1992)** — легендарным 3D-шутером, где игрок перемещается по лабиринту с видом от первого лица, используя технику **raycasting**.

## 🎯 Цель проекта

Создать собственный мини-движок от первого лица с использованием **MiniLibX**, который отображает карту в псевдо-3D и позволяет игроку двигаться по лабиринту.

Проект условно можно разделить на 3 фазы.
  
**Фаза 1** посвящена чтению, парсингу и валидации `.cub`-файла.

3️⃣ Парсинг карты (parse_map.c, map.c)
Что делаем:

Находим начало карты (первая строка после конфигурации, содержащая символы карты)
Считываем все строки карты в двумерный массив char **grid
Определяем ширину и высоту карты
Допустимые символы:

0 — пустое пространство (проходимо)
1 — стена (непроходимо)
N, S, E, W — стартовая позиция и направление взгляда игрока
  (пробел) — пустота за пределами карты

4️⃣ Проверка закрытости карты (bfs.c)
BFS vs Flood fill
Безопасность: Нет риска переполнения стека на больших картах
Контроль: Ты явно управляешь очередью, а не полагаешься на стек вызовов
Читаемость: Итеративный код проще отлаживать

Карта в cub3D должна быть полностью окружена стенами (1), чтобы игрок не мог "выйти" за её пределы. Если в карте есть дыра (пробел   на границе доступной области), это приведёт к неопределённому поведению при рендеринге.
Как работает BFS в проекте
Общий алгоритм:
Инициализация:

Создаём матрицу visited размером [height][width] (все значения = 0)
Создаём круговую очередь размером height × width
Добавляем стартовую позицию игрока в очередь
Помечаем стартовую клетку как посещённую (visited[y][x] = 1)
Обход в ширину:

Пока очередь не пуста:
Извлекаем клетку из очереди
Проверяем 4 соседних клетки (вверх, вниз, влево, вправо)
Для каждого соседа:
Если это 0 (пустая клетка) → помечаем как посещённую, добавляем в очередь
Если это 1 (стена) → игнорируем
Если это   (пробел) → ОШИБКА! Карта не замкнута
Результат:

Если все доступные клетки проверены без встречи с пробелами → карта валидна ✅
Если встретили пробел → карта невалидна ❌

Преимущества нашей реализации
✅ Безопасность: Нет риска переполнения стека
✅ Эффективность: O(width × height) — каждая клетка проверяется ровно один раз
✅ Память: O(width × height) для visited + O(width × height) для очереди
✅ Полнота: Гарантированно обходит все доступные клетки
✅ Детекция дыр: Моментально находит пробелы на границах
✅ Читаемость: Итеративный код легко отлаживать
Что такое "замкнутая" карта?
Замкнутая карта — это карта, где все доступные для игрока клетки (символы 0, N, S, E, W) окружены стенами (1). Игрок не должен иметь возможности "выйти" за пределы игровой зоны.

Ключевой критерий незамкнутости:
❌ Карта незамкнута, если любая доступная клетка (0) граничит с пробелом ( ).

Другими словами:

✅ Клетка 0 может соседствовать с 0 (другая доступная клетка)
✅ Клетка 0 может соседствовать с 1 (стена — граница игровой зоны)
❌ Клетка 0 НЕ МОЖЕТ соседствовать с   (пробел — пустота за картой)
Почему пробелы валидны, но опасны?
Пробел ( ) — это легальный символ в файле .cub. Он используется для:

Выравнивания карты (отступы слева)
Обозначения "ничего" за пределами игровой зоны
Пример валидного использования пробелов:

Code
        11111111  ← Пробелы слева для отступа (OK)
        10000001
        100N0001
        10000001
        11111111
Но если пробел граничит с доступной клеткой — это дыра:

Code
11111111
1000000   ← Пробел справа граничит с `0` — ДЫРА!
100N0001
10000001
11111111

typedef struct s_map
{
    char    **grid;        // Двумерный массив карты
    int     width;         // Ширина (макс. длина строки)
    int     height;        // Высота (количество строк)

typedef struct s_textures
{
    mlx_texture_t   *north;    // Текстура северной стены
    mlx_texture_t   *south;    // Текстура южной стены
    mlx_texture_t   *west;     // Текстура западной стены
    mlx_texture_t   *east;     // Текстура восточной стены

typedef struct s_player
{
    double  pos_x;         // Позиция X (в координатах карты)
    double  pos_y;         // Позиция Y
    double  dir_x;         // Направление взгляда X
    double  dir_y;         // Направление взгляда Y
    double  plane_x;       // Камера-плоскость X (FOV)
    double  plane_y;       // Камера-плоскость Y

typedef struct s_game
{
    t_map       map;
    t_textures  textures;
    t_player    player;
    uint32_t    floor_color;   // Цвет пола (hex)
    uint32_t    ceiling_color; // Цвет потолка (hex)
    mlx_t       *mlx;
    mlx_image_t *image;
} t_game;
